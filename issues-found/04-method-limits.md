# 04: Method limits that can't be fixed within this setup (disclosed, not bugs)
- **Test-frame leak in the pose tracker.** The skeleton is extracted from the whole sequence, test frames included, and the test-frame joint angles come from tracking the test surfaces. Only the outer bones (SSDR) and the LBS weights are fitted on training frames. Every arm gets the same query, so the comparison is fair, but absolute errors are optimistic. A clean version would extract the skeleton from training frames only and track the test frames without surface constraints. That needs changes to the upstream pipeline, so it wasn't done here.
- **The paper's numbers can't be reproduced.** The paper's garment benchmark (VTO) needs SMPL registration, and no trained Gaussian checkpoints are released. This is a fresh test of the PartMM idea on public AMA meshes. It says nothing about the 48.4% figure.
- **CPU only.** There's no GPU on the box. The mesh pipeline doesn't need one, but the Gaussian-splat rendering half of GaussiAnimate wasn't exercised at all.
- **Frame-level bootstrap intervals are too narrow.** Neighbouring frames are autocorrelated. The pre-registered verdicts use the sequence-level bootstrap. The frame-level and two-level bootstraps in `results/frame_bootstrap.json` are descriptive.
- **The design changed before the pre-registration.** DESIGN.md (v1) planned a robust-weight-transfer LBS baseline. PREREGISTRATION.md replaced it with NNLS-fitted weights on training frames, before any run. That's a stronger baseline than the paper's.
